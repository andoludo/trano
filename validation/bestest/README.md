# ASHRAE 140 (BESTEST) validation

The 27 cases of section 5.2 of ASHRAE Standard 140-2020 are described as trano YAML files
(`cases/`, generated by `cases.py`), simulated with each library, and their KPIs compared with the
reference data vendored in `spec/` (annual loads against the acceptance limits of the standard,
peak loads and free-floating temperatures against the spread of the reference programs).

```bash
python -m validation.bestest list                       # cases and whether their YAML is generated
python -m validation.bestest generate                   # rewrite the YAML files in cases/
python -m validation.bestest run 600 900FF --library Buildings --workers 3
python -m validation.bestest report                     # Markdown and JSON in _reports/
pytest -m bestest                                       # gate: Buildings and IDEAS must pass
```

A case takes a few minutes in Docker; the results are cached in `.cache/bestest` by the generated
model, so an unchanged case is read back instead of simulated again. Cases run in separate
processes (`--workers`), each in its own container.

Installed Modelica libraries can be mounted into the containers from the directory named by the
environment variable `TRANO_MODELICA_LIBRARIES` (OpenModelica's package layout, `Buildings 13.0.0`
and so on), which keeps the package manager and the network out of the loop. Without it the
libraries are installed at every container start.

Results outside their band that are understood are listed in `report.KNOWN_DEVIATIONS` with their
reason; the gating test accepts them and the report shows them. The scheduled workflow
`.github/workflows/bestest.yaml` runs the matrix weekly and on demand and keeps the report as an
artifact; `docs/validation/bestest.md` is rendered from the cached results with
`python -m validation.bestest report --docs`.
